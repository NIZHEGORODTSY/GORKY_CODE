# GORKY_CODE — голосовой ассистент для задач и встреч

Этот файл читают Claude-агенты всех участников команды. Над проектом одновременно работают
несколько людей, у каждого свой Claude. Напрямую агенты общаться не могут, поэтому **единственный
канал связи — этот репозиторий и GitHub** (см. «Протокол координации»). Соблюдай его строго.

Репозиторий: https://github.com/NIZHEGORODTSY/GORKY_CODE (публичный, ветка по умолчанию `main`).

## Что делаем

Тестовое задание: прототип голосового ассистента, который по свободной речи (голосом или текстом)
создаёт задачи/напоминания и встречи, показывает планы на период и ищет старые записи.
Полная сводка требований и критериев оценки — [docs/SPEC.md](docs/SPEC.md). Перед любой работой
над фичей сверься с ней.

Обязательный минимум (4 действия + сохранение данных между запросами):
1. создание задачи / напоминания;
2. создание встречи;
3. список задач и встреч за период («что у меня сегодня / на неделе»);
4. поиск ранее созданной записи по смыслу («найди задачу про договор»).

Главное в оценке — логика: понимание естественной речи, относительные даты, уточняющие вопросы,
чистое разделение слоёв (голос / LLM / бизнес-логика / хранение). UI может быть минимальным.

## Стек и архитектура

> Статус: **предложение, ещё не утверждено командой.** Когда решение принято — отметь его в
> [docs/STATUS.md](docs/STATUS.md) в разделе «Решения» и убери эту пометку.

- **Backend:** Python 3.11+, FastAPI.
- **LLM:** Claude API с tool use (модель `claude-sonnet-5-5`). LLM не пишет в БД сама — она
  выбирает инструмент и заполняет аргументы, а бизнес-логика их валидирует и выполняет.
- **Хранение:** SQLite через SQLAlchemy (файл БД не коммитим).
- **Поиск:** гибрид — полнотекстовый (SQLite FTS5) + семантический (эмбеддинги), с фильтром по датам.
- **Голос:** в браузере — Web Speech API (STT, `ru-RU`) и `speechSynthesis` (TTS). При
  необходимости заменяется на серверный STT/TTS без изменения бэкенда.
- **Frontend:** одна статическая страница (кнопка записи, история диалога, ответ), раздаётся FastAPI.
- **Деплой:** нужна публичная ссылка на работающий прототип (Render / Railway / Fly — решить).

Предлагаемая структура (каждый модуль — зона ответственности, которую можно взять целиком):

```
app/
  api/        # FastAPI-роуты: POST /chat, GET /events, раздача web/
  assistant/  # оркестрация диалога: история, контекст («перенеси её»), уточняющие вопросы
  llm/        # клиент Claude, системный промпт, JSON-схемы инструментов
  core/       # бизнес-логика: модели Event, разбор дат, валидация, конфликты встреч
  storage/    # SQLAlchemy-модели, репозиторий, миграции
  search/     # FTS + эмбеддинги, ранжирование
web/          # index.html + js: запись голоса, TTS, чат
tests/
docs/
```

### Контракт данных (менять только через согласование в STATUS.md)

`Event`:
| поле | тип | комментарий |
|---|---|---|
| `id` | int | |
| `kind` | `task` \| `reminder` \| `meeting` | |
| `title` | str | содержание задачи / название встречи |
| `starts_at` | datetime \| null | для задачи — срок, для встречи — начало |
| `ends_at` | datetime \| null | только для встреч |
| `all_day` | bool | дата без времени («в пятницу отправить отчёт») |
| `status` | `open` \| `done` \| `cancelled` | |
| `created_at` | datetime | |

Все даты хранятся с таймзоной. Текущие дата/время и таймзона пользователя всегда передаются в LLM
явно — модель не должна угадывать «сегодня».

Инструменты LLM (минимум): `create_event`, `list_events(from, to, kind?)`, `search_events(query,
from?, to?)`, `ask_clarification(question)`. Дополнительно: `update_event`, `delete_event`,
`complete_event`.

## Протокол координации между участниками и их Claude

**В начале каждой сессии**, до любых изменений:
1. `git pull` (или `git fetch` + сверка, если есть локальные изменения).
2. Прочитай [docs/STATUS.md](docs/STATUS.md) — кто чем занят, принятые решения, сообщения тебе.
3. `gh issue list` и `gh pr list` — открытые задачи и PR.

**Задачи** живут в GitHub Issues. Перед началом работы:
- выбери свободный issue (или создай его), назначь своего человека: `gh issue edit <N> --add-assignee @me`;
- впиши строку в таблицу «Кто чем занят» в STATUS.md, закоммить и запушь это **сразу**, чтобы другой
  агент увидел, что задача занята.

**Ветки и PR:**
- в `main` напрямую не пушим; ветка на задачу: `<github-login>/<короткая-тема>`, например
  `petushok08/llm-tools`;
- PR маленькие, в описании — `Closes #N`, что сделано и как проверить;
- чужие модули (занятые в STATUS.md) не правим молча — сначала сообщение (см. ниже);
- перед PR: `git fetch && git rebase origin/main`, тесты проходят.

**Сообщения другому участнику / его Claude:**
- по конкретной задаче — комментарий в её issue или PR;
- общее (вопрос по архитектуре, изменение контракта, блокер) — в STATUS.md, раздел «Сообщения»,
  в формате `- [YYYY-MM-DD] <от кого> → <кому>: текст`. Когда ответили/учли — перенеси в «Решения»
  или удали.
- Подписывай текст от агента: `— Claude (<github-login человека>)`, чтобы было понятно, кто писал.

**В конце сессии:** обнови свою строку в STATUS.md (что сделано, что дальше), запушь ветку.

## Правила кода

- Код и идентификаторы — на английском; комментарии, документация, сообщения в STATUS — на русском.
- Коммиты: `feat: …`, `fix: …`, `docs: …`, `refactor: …`, `test: …` (текст можно по-русски).
- Секреты (`ANTHROPIC_API_KEY` и др.) — только в `.env`, который в `.gitignore`. Новые переменные
  окружения добавляй в `.env.example` без значений.
- Бизнес-логику (разбор дат, валидация, поиск) покрываем тестами `pytest`; LLM в тестах мокаем.
- Не плодим зависимости без нужды; новую зависимость — в `requirements.txt` и упоминание в PR.
